[![Image 1](https://thumb.wikimedia.org/wikipedia/commons/thumb/4/4d/Agent_harness.png/250px-Agent_harness.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:Agent_harness.png)

[OpenAI](https://en.wikipedia.org/wiki/OpenAI "OpenAI")[Codex](https://en.wikipedia.org/wiki/OpenAI_Codex_(AI_agent) "OpenAI Codex (AI agent)") agentic harness working under the hood with the [Tauri (software framework)](https://en.wikipedia.org/wiki/Tauri_(software_framework) "Tauri (software framework)")[DOM Inspector](https://en.wikipedia.org/wiki/DOM_Inspector "DOM Inspector")

An **agent harness**, also known as **agent scaffolding**, is the software infrastructure surrounding a [large language model](https://en.wikipedia.org/wiki/Large_language_model "Large language model") (LLM) that enables it to operate as an [AI agent](https://en.wikipedia.org/wiki/AI_agent "AI agent"). It manages tool use, memory, state persistence, execution environments and feedback loops, as opposed to the model's internal reasoning.[[1]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Yehudai2026-1)[[2]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-VB-Harness1-2) The UK's [AI Security Institute](https://en.wikipedia.org/wiki/AI_Security_Institute "AI Security Institute") described an AI agent as being formed by the model plus the scaffolding back in 2023.[[3]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-3) The relationship can be expressed as _agent = model + harness_.[[4]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Fowler-4)

Because a "base model" LLM is a [stateless](https://en.wikipedia.org/wiki/Stateless_protocol "Stateless protocol") probabilistic function that maps input token sequences to output token sequences, the harness is what makes an agent out of a model, i.e. a thing that interfaces with external tools, inputs and outputs non-token data (such as images), and interacts with a task-environment coherently over many rounds. Rather than repeatedly re-reading an ever-growing transcript inside the [context window](https://en.wikipedia.org/wiki/Context_window "Context window"), a harness can offload record-keeping into a structured software environment that manages the agent's state.[[2]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-VB-Harness1-2) A minimal harness is unnecessary for a single prompt-and-response exchange, but becomes important as tasks grow multi-step, tool-oriented, or long-running.[[5]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-VB-SelfHarness-5)

Popular agent harnesses are focused on [AI-assisted software development](https://en.wikipedia.org/wiki/AI-assisted_software_development "AI-assisted software development"), including [Anthropic](https://en.wikipedia.org/wiki/Anthropic "Anthropic")'s [Claude Code](https://en.wikipedia.org/wiki/Claude_Code "Claude Code"), [OpenAI](https://en.wikipedia.org/wiki/OpenAI "OpenAI")'s [Codex](https://en.wikipedia.org/wiki/OpenAI_Codex_(AI_agent) "OpenAI Codex (AI agent)"), [Google DeepMind](https://en.wikipedia.org/wiki/Google_DeepMind "Google DeepMind")'s [Antigravity](https://en.wikipedia.org/wiki/Google_Antigravity "Google Antigravity"), [SpaceXAI](https://en.wikipedia.org/wiki/SpaceXAI "SpaceXAI")'s [Cursor](https://en.wikipedia.org/wiki/Cursor_(company) "Cursor (company)"), [Qwen](https://en.wikipedia.org/wiki/Qwen "Qwen"), [DeepSeek](https://en.wikipedia.org/wiki/DeepSeek "DeepSeek"), [Kimi](https://en.wikipedia.org/wiki/Kimi_(AI) "Kimi (AI)"), and [GLM](https://en.wikipedia.org/wiki/GLM_(AI) "GLM (AI)").

The mechanisms that a harness coordinates predate the term. The pattern of a model alternating between reasoning and acting in a loop was introduced in the peer-reviewed ReAct framework,[[6]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-ReAct-6) and the ability of a model to call external tools was demonstrated in Toolformer.[[7]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Toolformer-7)

Components commonly grouped under a harness include tool dispatch, memory and state persistence, an isolated [sandbox](https://en.wikipedia.org/wiki/Sandbox_(computer_security) "Sandbox (computer security)") or workspace, context management, and guardrails such as scoped permissions, approval tiers and monitoring. In a 2026 engineering write-up, Anthropic described a worked example built from an initialiser agent that prepares the environment and a coding agent that repeatedly selects the next unfinished task, commits, and updates a progress record before stopping.[[8]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Anthropic-8)

Birgitta Böckeler of Thoughtworks distinguishes an _inner harness_ shipped by the model's builder (for example an agent SDK or a coding tool such as Cursor or Codex) from an _outer harness_ that the user assembles on top, such as instruction files, [Model Context Protocol](https://en.wikipedia.org/wiki/Model_Context_Protocol "Model Context Protocol") servers and custom skills. She further separates _guides_, which steer the agent before it acts, from _sensors_, which observe the result and let the agent self-correct; each may be _computational_ (deterministic checks such as linters or tests) or _inferential_ (semantic checks such as an "LLM as judge").[[4]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Fowler-4)

## History and terminology

[[edit](https://en.wikipedia.org/w/index.php?title=Agent_harness&action=edit&section=2 "Edit section: History and terminology")]

Related notions of scaffolding around a model exist in software testing (the [test harness](https://en.wikipedia.org/wiki/Test_harness "Test harness")), in LLM benchmarking (evaluation harnesses), and, in [reinforcement learning](https://en.wikipedia.org/wiki/Reinforcement_learning "Reinforcement learning"), in the environment and wrapper that surround a learning agent.[[4]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Fowler-4) The nouns _agent harness_ and _LLM harness_ circulated among practitioners before the associated discipline was named.

The vocabulary of "harness engineering" emerged in early 2026, and attribution of the specific phrase is contested. Several accounts trace it to a February 2026 blog post by [Mitchell Hashimoto](https://en.wikipedia.org/wiki/Mitchell_Hashimoto?action=edit&redlink=1 "Mitchell Hashimoto (page does not exist)"), co-founder of [HashiCorp](https://en.wikipedia.org/wiki/HashiCorp "HashiCorp"), who described a practice of engineering a permanent fix into an agent's environment each time it makes a mistake;[[4]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Fowler-4) other accounts credit Vivek Trivedy of LangChain, whose "Anatomy of an Agent Harness" post derived the harness components from the _agent = model + harness_ formula.[[9]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-OReilly-9) A widely cited OpenAI engineering report describing a large codebase built largely by coding agents, together with follow-on writing from Thoughtworks, LangChain and Anthropic, helped spread the term.[[4]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Fowler-4)[[8]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Anthropic-8)

By mid-2026 the harness had become an object of academic study. Independent reporting described research such as Self-Harness, in which an agent iteratively mines its own failures to propose and validate changes to its harness,[[5]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-VB-SelfHarness-5) and Harness-1, an open-source search agent that improved retrieval accuracy chiefly by redesigning the software environment around the model rather than by enlarging the model.[[2]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-VB-Harness1-2)

## Relationship to prompt and context engineering

[[edit](https://en.wikipedia.org/w/index.php?title=Agent_harness&action=edit&section=3 "Edit section: Relationship to prompt and context engineering")]

Harness engineering is often positioned as a broader layer than [prompt engineering](https://en.wikipedia.org/wiki/Prompt_engineering "Prompt engineering"), which optimises a single interaction, or context engineering, which governs what information the model sees at a given moment; in this framing the harness designs the whole operational environment and contains the other two as parts.[[4]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-Fowler-4) A distinguishing feature is that the component being wrapped is non-deterministic, so a harness is designed to recover gracefully when the model fabricates an action or reports a task as finished when it is not.[[5]](https://en.wikipedia.org/wiki/Agent_harness#cite_note-VB-SelfHarness-5)
